# Local Wind and timeline preview

This feature is included in Cloth NeXt 2.9.18.

Enable **Local Wind Field** on a Cloth NeXt Force Empty. Wind follows its local +Z direction and fades to zero at **Radius**. **Falloff** concentrates the flow around the Empty. **Turbulence** adds bounded, spatially varying swirling air velocity; **Swirl Size** sets its spatial wavelength and the existing **Noise Scale** sets its temporal period. Animate the Empty or these physical properties normally.

Enable **Show Wind Vectors** and scrub or play the timeline before baking. The overlay reads the current evaluated transforms and animated values, then uses the same local velocity evaluator as export. It never changes the timeline, creates a Bake cache or starts a solver. **Vector Scale** affects display only. The preview draws combined local fields plus legacy global Wind near geometry selected by **Obstacles**: Colliders in Collider mode, scene surfaces in Scene Geometry or Off mode. Separate objects receive separate sampling areas, leaving empty gaps without arrows. Simulation targets are included as preview locations in scene modes, while remaining excluded from obstacle response. Collection instances and moving objects follow the evaluated timeline. Arrows are bounded per object and respect Blender's overlay visibility toggle.

**Obstacles** selects **Off**, **Cloth NeXt Colliders** (the default), or **Scene Geometry**. Scene Geometry also includes surfaces without a Collider setup: Mesh, Curve, Surface, Font and Metaball objects. Active Cloth NeXt simulation targets are excluded so a previous Bake cache cannot shield a target from its own Wind. Prescribed obstacle transforms and deformation follow the timeline; the native simulation's newly computed cloth motion is not fed back into the air field.

The obstacle model traces upstream through evaluated triangle geometry, weakens the downstream flow, diverts incoming velocity near surfaces and adds a bounded time-dependent swirling wake. Air velocity inside closed meshes is zero. **Wake Strength** changes the transverse wake motion; zero retains the shadow and surface deflection. **Wake Length** changes downstream recovery relative to obstacle size. Effects end at the Wind source's radius. This is a controllable approximation rather than a pressure/CFD solve; the legacy global Wind contribution retains its previous behavior.

Repeated viewport redraws reuse vector buffers and GPU batches. A bounded geometry cache reuses static obstacle BVHs across frames; geometry edits invalidate affected objects, while animation and transforms select updated surfaces. A bounded query cache shares unchanged surface responses across emitters and frames, and vectorized bounding-box tests prune irrelevant obstacle queries. Uniformly transformed preview meshes use Blender's native BVH construction; export retains world-space geometry queries. Collider input boundaries without downstream modifiers use their existing evaluated mesh, avoiding temporary objects and repeated whole-scene dependency updates. UI cache status reads only obstacle properties and dependencies. Full obstacle mesh identity belongs to explicit validation's geometry fingerprint; Scene-mode obstacle edits mark simulation geometry dirty without mesh scans in handlers. Exported field bytes also authenticate recovery.

Local fields require official GAIA 0.23 and positive Air Density. They are exported as `air-velocity` grids, retain normal aerodynamic drag, and do not also contribute to the global Wind vector. Legacy Wind remains unchanged when Local Wind Field is off. Existing Water Flow streaming retains these grids as base fields when replacing its held windows.

Every output frame is sampled with its actual Blender pose and values; the original frame and subframe are restored even on cancellation. Bounds cover the moving source across the range, spacing follows the smallest source radius and selected Field Resolution, and combined uncompressed field schedules are limited to 32 MiB before allocation. Large source motion can increase grid size substantially. The solver interpolates grid nodes in space and samples in time: the viewport evaluator is continuous, so very coarse grids or rapid changes between frames can differ from the preview. Raise Field Resolution for small swirls.

Bake preparation reports local Wind animation capture, **Sampling local Wind**, and field encoding separately. Progress counts completed capture frames, sampling frames and encoded sources, with updates throttled to ten per second and explicit phase boundaries. These are preparation work units, not simulated frames or a predicted time remaining. Geometry preparation without a known total stays indeterminate instead of showing a fixed zero percent. Cancel remains available during field capture, obstacle queries and between encoded sources.

The native global Wind has its own multiplier, `0.875 + 0.125*sin(30*t)`, with `t` relative to Bake Start. Authored air-velocity fields bypass it. Replacing existing global Wind with a local field therefore intentionally changes its temporal response; the implementation preserves the legacy path and applies this multiplier only to the global contribution in the preview.

Validation on 2026-10-12:

- Pure tests cover finite inputs, exact support boundaries, translation, direction, superposition, bounded deterministic turbulence, float32 preview arrows and byte-exact agreement with the existing official grid axis conversion.
- Real Blender tests cover pre-Bake preview, keyframed location and strength, temporal turbulence, frame/subframe restoration, rejected older protocols and duplicate-free load/frame handlers.
- Two actual GPU captures at frames 1 and 60 contain visible Wind arrows and different pixels.
- A native CUDA test consumed the grid exported by Blender: mean displacement inside the source was 0.14659; maximum displacement outside was 4.47e-8.
- Earlier 20-frame native comparisons confirmed group targeting and spatially different cloth motion. Equal nominal global/grid Wind speeds were deliberately not treated as equivalent because of the native global gust multiplier.
- Obstacle regressions cover geometry outside Collider setup, animated motion, source-specific shadow direction, mirrored transforms, closed-mesh interiors, geometry-edit invalidation and cancellation without leaked Blender data.
- Native CUDA comparison behind a scene-only obstacle: mean forward displacement was 0.39807 with Obstacles Off, 0.39807 in Collider-only mode, and 0.21191 in Scene Geometry mode. Transverse RMS displacement increased from 0.00021 to 0.04629 with the authored wake.
- Performance regression checked in a live animated character scene with approximately 169,000 triangles. With Grooms disabled, complete frame changes including Wind preview averaged 48 ms in Collider mode (previously 663 ms), and 87 ms in Scene mode (previously 5.39 s). Three-frame Wind preparation dropped from 8.22 s to 0.41 s in Scene mode, with byte-identical exported payloads. This measures Wind preparation rather than native simulation time; dense animated scenes can still exceed realtime frame budgets. `tools/blender_wind_scene_performance.py` reproduces saved-scene workloads, and `tools/blender_wind_performance.py` supplies a small synthetic workload.
- A subsequent live UI profile found full Wind obstacle mesh hashes in the floating Bake status path even with Wind vectors disabled. Moving those hashes to validation reduced a complete status check from 88.9 ms to 2.8 ms. Real Blender regression checks 100 UI fingerprints without mesh capture and verifies that scene-only obstacle edits still dirty validation and change the geometry fingerprint.

The current implementation uses Cloth NeXt Force Emptys. It does not import arbitrary Blender native Force, Vortex or Turbulence objects. CFD and per-object field authoring are outside this change.
